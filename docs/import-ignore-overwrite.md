# AI 匯入：忽略或覆蓋既有行程

貼回 AI JSON、按「檢查內容」後，重複行程會標出原卡片，預設選擇「忽略，保留原行程」。改成「覆蓋，更新原行程」並確認匯入才會寫入；若有多筆相符原卡，必須再選一個覆蓋目標。全部忽略時按「完成（全部忽略）」即可結束，不改資料。

可同時新增與覆蓋。確認前顯示新增／覆蓋筆數，完成後顯示新增卡片與覆蓋行程數，並提供短時間的「復原」。住宿仍是一筆訂單、入住／退房兩張卡。

## 怎麼判斷重複

- 僅比對這趟旅程的同類型卡片，退房子卡不作為獨立目標。
- 有相同訂單編號時可找出改名或改期的訂單；航班還要區分航段方向，不能單憑 PNR 把去回程混用。
- 沒有足夠編號時比對同日期、同類型與同名稱；忽略空白、英文大小寫與住宿「入住」字尾。未排程卡可用原日期比對。
- 雙方都提供編號且不同，不會只因同名同日而建議覆蓋。
- 同名多候選不自動挑第一筆。同一批相同行程預設略過後面的重複項；一次不能選兩筆覆蓋同一目標，避免最後一筆默默勝出。

這是輔助比對，不是訂單真偽驗證。若名稱、編號與日期都改變，可能無法辨識同一筆；請人工核對，避免另增重複卡。

## 覆蓋保留什麼

| 資料 | 處理 |
| --- | --- |
| 有效新值 | 更新原卡；明確數字 0／布林 false 可更新 |
| null、未提供、空字串／空清單 | 保留原資訊，不把未知行李、早餐或金額覆成 0／false |
| 新筆記有內容 | 取代原筆記，不追加成兩段長文；空筆記保留舊筆記 |
| 原卡片 ID／PDF 等附件 | 保留；不刪除或重新附到新卡 |
| 手動備案／待辦／停留等匯入不支援欄位 | 保留 |
| 提醒偏好 | AI 未提供時保留原值，明確 true／false 才更新 |
| 住宿雙卡 | 保留主卡、退房卡 ID，同步名稱與日期時間；保留退房卡自己的手寫筆記與附件 |
| 原本單卡的手動住宿 | 有完整退房日才補建退房卡，計入新增卡片數，不重建主卡 |
| 票種 | 依唯一同名票種保留未提供的單價／張數，再依有效資訊計算總價 |
| 交通路線 | 有完整新路線才替換該行程路線；空路線保留原路線，不刪其他行程的路線。同名且唯一的路線沿用 ID，保留手動訂票資訊／說明與未提供的付款、預訂狀態 |
| 排序 | 日期、開始時間不變時保留原手動位置；新增或改期改時才依時間插入，其餘相對順序保留 |

想清空已知欄位或移除附件，請到原行程編輯／附件管理操作；這份 AI 匯入不把 null 當刪除指令。新日期超出旅程時，預覽明示將移到未排程，保留真實原日期。

## 寫入與復原

保存時會重新查詢本機資料庫。原卡片欄位若已在預覽後修改、被刪除、變成其他旅程或新增了相同行程，會要求重新檢查，不會自動覆蓋。來源沒有足夠交通工具／分鐘／費用，或住宿日期與雙卡關聯不合法時，會停止並提示補齊。

新增、覆蓋、排序與路線在同一筆 IndexedDB transaction 寫入，失敗整批回滾。「復原」會移除本次新建卡、還原原卡、交通路線與排序；既有附件在覆蓋過程沒有刪除。JSON 仍是 version 2，不新增資料庫 schema，也不接受 AI 指定資料庫 ID 或覆蓋操作。

實作：`importDuplicates.ts` 判斷候選、`importer.ts` 準備預覽、`importStore.ts` 合併／交易保存、`Plan.tsx` 提供選擇與復原。完整驗證與候選畫面見 [本次交接](handoffs/2026-11-08-import-ignore-overwrite.md)。
