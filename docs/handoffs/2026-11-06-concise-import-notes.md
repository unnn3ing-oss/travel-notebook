# 任務交接：依核對報告精簡 AI 匯入筆記

- 日期：2026-11-06（Asia/Taipei）
- 狀態：planned
- 正式版／本機基準：35f964f0425df4eabcedc9c8ba83983ffd55d561，work 分支
- 授權：使用者要求依旅行資料優化提示詞，現已提供另一對話的核對報告；實作與驗證，不包含本次 main 合併／部署。
- 私人來源：使用者提供的核對報告只在此對話附件，不上傳 GitHub、不寫入 fixtures 或截圖。沒有直接讀取真實 Gmail／Notion／PDF，不把報告的核驗聲稱當成本 AI 親自驗證。

## 使用者需求

目前 App 筆記過長，混入來源、附件名稱、查核過程與重複欄位。依提供的旅行報告修正匯入提示詞，讓內容正確、簡單、容易讀；保留真正影響行動的提醒。

## 修改方向

1. notes／hotel.note 預設最多 3 個短項、每項一個行動；無提醒填 null，不湊字數。不硬截斷關鍵限制，不讓筆記重複地址、價格、PNR、一般政策或來源敘述。
2. JSON 維持 version 2，新增可選根層 review 陣列，集中來源、缺漏、衝突及排除紀錄；它是外部 AI 對話的核對區，現有 App 不把它匯入筆記。不改 DB 或引入新 UI。
3. 明確核對有效訂位／版本、已取消訂單、新付款取代舊扣款計畫、Notion 個人規劃不是已購票、Notion 引用 PDF 不代表當次讀過原附件。
4. 確認訂單與已付款分開；尚待自動扣款不可填現場付款，現有 payment 無此列舉時填 null，必要時用一行短筆記描述扣款待確認。跨日抵達日期不因旅程最後一天截掉；取消期限現有欄位只支援日期，必要精確時間另用短提醒。
5. 在目前支援的 car 欄位範例補租車取還地點／重要步驟與附加服務，不為同筆租車的附加服務重複建單。不新增專屬租車資料模型。
6. 僅修改 src/lib/importer.ts 的提示詞／範例與相關回歸驗證、文件；不自動清理、截斷或改寫既有使用者筆記。舊長筆記需重新產生並確認後處理，不能承諾提示詞改了就會回溯變短。

## 驗收與驗證

- 使用虛構資料驗證 review 不混入筆記、待扣款與未知欄位不變成已付／現場付款、跨日航班日期保留、租車附加事項不重複成新單。
- npm test、npm run build；瀏覽器檢查實際複製提示詞及簡短匯入筆記、住宿雙卡、資料重載保留。提供不含使用者私密資訊的示範截圖。
- 保留最新 UI、原始手動筆記與舊格式 JSON 相容性；不增加硬截斷。沒有直接驗證原始私信或附件。

## 接手狀態

尚未改程式，先保存計畫。已讀完整報告與現有提示詞；找到舊提示詞要求把來源與 PDF 檔名寫 notes，且要求完整原文，導致筆記過長。工作區乾淨、main 無新變更。確認 checkpoint pushed 後實作。

純文件 checkpoint 不是程式備份；不要將附件的私人訂單編號、姓名、地址、信箱、Notion 私人頁面連結或完整報告放進 repo。
