## 使用者需求

現行只用同日同名取消勾選，使用者希望能明確選擇「忽略」或「覆蓋」已有行程。保留現有品牌設計與先預覽再寫入流程，住宿雙卡、交通路線、附件、排序與提醒不得毀損。

## 修改方向

1. 重複判斷先同類型／訂單編號，再看同日同類型同名稱（住宿忽略入住字尾）；訂單編號不同不能因同名自動覆蓋。航班同 PNR 需區分航段／方向，不混去回程。跨日改期可依相同有效訂單識別候選，未排程原日期也可比對。退房子卡不當獨立覆蓋目標。
2. 預覽每個重複項目提供忽略／覆蓋，預設忽略；顯示對應原卡日期／名稱。多個候選時明確選目標，不自動選第一筆。批次重複項目預設略過，一次不得覆蓋同個 ID 兩次或把同筆新增兩次。
3. 覆蓋是更新 AI 有提供且有效的資料；null／未提供不清掉已知值，明確 0／false 可更新。保留原 ID、附件、手動備案／待辦與偏好；新筆記有內容則取代原筆記，空值不清空；住宿入住／退房原 ID 連動更新，保留各自附件與手寫退房筆記。
4. 新 writer 包在單一 Dexie transaction；重新查 DB 校驗預覽目標仍存在、同旅程、同類型與相符，偵測預覽後修改。失敗整批回滾，錯誤不宣稱部分已加入。
5. 交通新路線有完整有效內容才覆蓋指定卡的路線；空路線保留原路線，不能清掉其他卡資料。票種未知數值不把已知價格／張數覆成 0，部分資料保留對應原票種已知值。
6. 未改日期／開始時間的卡保留原手動順序；改期／改時與新增才依時間插入，保留其餘相對排序。支援本次新增＋覆蓋一起復原，恢復原卡／路線與排序，不動附件。
7. 更新匯入成功統計、錯誤／重檢查操作，以及「複製提示詞」與欄位文件的舊「不支援覆寫」說明；同步共用範例，不改 JSON v2 格式或 DB schema。

## 驗收與驗證

- 重要單元／fake IndexedDB 整合：忽略不寫、同訂單改名／改期、去回航段分離、不同編號不誤判、多候選／批次重複／跨旅程／預覽後變更防護。
- 實際覆蓋保留 ID／PDF／已知座位、行李、早餐、票種與提醒偏好；明確 false／0 更新；筆記取代不拼接長文。
- 住宿雙卡改期且 ID 不變，附件／子卡筆記保留；交通只更新選定卡路線，空路線保留；原手動順序保持、改期插入正確；復原恢復整批；異常整批回滾。
- npm test、npm run build、git diff --check。
- 隔離 Chromium 新增與覆蓋混合、忽略、再匯入不增加張數、資料重載、復原、320／390 手機截圖。全部用虛構訂單與附件，不碰使用者資料。
