# 任務交接：待填任務名稱

- 日期：待填（Asia/Taipei）
- 狀態：planned / in_progress / awaiting_review / blocked / completed
- 正式版基準：待填完整 origin/main SHA
- 工作分支：待填
- 本次授權：待填；區分交接文件、程式推送、合併 main 與部署
- 相關使用者設計／來源：待填；標明是否已保存在 repo

## 使用者需求

待填：用自己的話準確保留本次需求、使用者補充與不能變動的行為；勿放秘密或真實訂單。

## 修改方向

待填：預計做法、涉及檔案、資料相容處理、理由與驗收範圍。尚未決定的事情列出來，不要冒充使用者已確認。

## 驗收與驗證

待填：需要執行的檢查、代表操作與截圖。完成後分別記錄實際結果與未跑項目，不得把舊結果寫成本次通過。

## 接手狀態

待填：修改前為「尚未改程式，先保存此計畫」。開始後更新完成／未完成項目、分支／SHA、未提交檔案、阻礙及下一個 AI 的第一步。

## Checkpoint 紀錄

- 待發布後補上實際 handoff 分支、SHA 與 GitHub 連結。
- 請記錄文件對應的來源狀態；沒有 commit 遠端程式時明確寫「程式僅在本機，交接文件未包含其 diff」。
