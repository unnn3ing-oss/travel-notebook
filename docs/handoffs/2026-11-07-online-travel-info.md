## 使用者需求

在 App 中依目的地自動更新天氣、交通及景點資料；沿用現有深藍／黃設計，聯網更新、離線保留已取得內容。不是本次複製提示詞修改或信箱同步。不得承諾 App 有真實訂單／附件同步權限。

## 修改方向

1. 總覽與旅途中「今日」新增共用旅途資訊卡：城市、更新狀態、天氣／交通／景點三個小分頁、手動更新與自動更新開關。保留舊卡、提醒、編輯、排序與資料庫 schema。
2. 城市先依旅程名稱的明確城市或最早抵達航班目的地推定常見城市，允許使用者搜尋並選定其他城市；城市中心周邊不等於住宿附近，不索取定位。搜尋多筆時必須由人選，不把模糊城市當已確認位置。
3. 天氣使用 Open-Meteo 公開預報，顯示日期、天氣、最低／最高溫、降雨機率與來源。以 API 實際回傳的日期為準，旅程超出預報期時明示，不能當成旅行日天氣。
4. 車站／景點使用中文 Wikipedia 公開附近查詢與摘要、座標、類別；按座標距城市中心排序，有限筆數、文字呈現、標示來源／授權。交通是車站介紹，不是即時班次／延誤；另附對應地區官方交通查詢入口並明確標示人工開啟，不宣稱自動取得官方營運狀態。
5. 公開資料僅查詢城市及城市中心座標，不送訂位、住址、筆記、旅客或附件；不新增後端／金鑰，不會自動改動行程與訂單。
6. App 開啟且前景時，啟用自動更新後於初次／重新連線／回前景與合理週期檢查更新；天氣 30 分鐘、百科 24 小時快取，失敗退避。分別保留最後成功結果／時間，顯示過期／離線／部分失敗；手動更新可重試。關閉 App 不保證背景執行。
7. 獨立 localStorage 版本快取／設定；壞資料或儲存失敗不使 App 白畫面；中止切城／離頁過期請求；不跨城市混用快取。自動更新可關閉，仍可手動更新。
8. 公開地圖 Overpass 主站 406、另一實例逾時，已嘗試後改用可用的 Wikipedia 公開 API；不是改網路政策。Open-Meteo geocoding／weather 與 Wikipedia 查詢已用 curl 實際取回資料，尚待瀏覽器驗證 CORS。

## 驗收與驗證

- 重要資料解析測試：天氣未知／零值／日期範圍，城市推定與明確選擇，車站／景點分類、去重、排序、惡意網址與不完整回應；城市隔離、快取有效期限、失敗保存最後成功內容與退避。
- npm test、npm run build、git diff --check。
- 隔離 Chromium 真實 API 煙霧驗證（包含 CORS），並用明確標示的網路模擬覆蓋離線／重連／部分失敗／切城市競態／停用自動更新；未真實驗證的班次、交通延誤、iOS 背景不可宣稱通過。
- 提供 320／390 手機畫面的天氣、交通、景點及離線快取截圖。確認使用者原本資料沒有變動。
