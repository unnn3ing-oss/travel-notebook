# 聯網旅途資訊

總覽與旅途中「今日」頁下方新增「旅途資訊」。依明確的旅程城市名稱或最早抵達航班的機場推定常見城市；可「更換城市」搜尋其他地方並選擇結果。同名城市不自動選第一筆。資訊範圍是城市中心，不會讀取裝置定位，也不等於住宿附近。

## 自動收集的內容

| 項目 | 資料來源與範圍 | 更新間隔 |
| --- | --- | --- |
| 天氣 | Open-Meteo，最多 16 天預報，顯示可取得的旅行日，最多列七天；若旅程超出範圍，清楚標示顯示近期天氣 | 成功取得後 30 分鐘 |
| 交通 | 中文 Wikipedia 城市中心約五公里內的車站、機場或碼頭介紹，最多六筆，預設先三筆；附來源與地圖入口 | 成功取得後 24 小時 |
| 景點 | 同範圍內可分類為博物館、公園、名勝等的百科資料與短摘要，最多六筆，預設先三筆 | 與交通共用一次查詢，24 小時 |

車站與景點依直線距離排序，不代表路程時間、推薦等級或目前開放。百科摘要刪除部分讀音註記並截短，標示 CC BY-SA，全文與修訂紀錄可由各筆來源開啟。

交通區另附地區官方交通查詢入口，供使用者開啟確認。**目前沒有自動取得即時班次、延誤、停駛、航班動態、景點營業／票價變更或營運公告**，不可把百科車站介紹當成即時營運狀態。沒有串接 Gmail／Notion 或讀取訂單 PDF，也不改 AI 匯入提示詞。

## 更新與離線

- 自動更新預設開啟，每趟旅程可關閉；關閉後仍可按「立即更新」。城市與開關保存在此裝置。
- App 在前景時於初次進入、重新連線、回到前景與每分鐘檢查是否需要更新；仍遵守各來源快取間隔。關閉 App 或在背景時不保證執行，也沒有背景推播。
- 失敗後至少五分鐘再自動重試；真正離線轉回上線可立即重試，重複 online 事件不清掉退避。手動更新可立即重試。
- 天氣與百科獨立處理。任一來源失敗仍保留自己的上次成功資料與原時間，不把失敗嘗試算成成功更新。
- 離線顯示快取、取得時間與過期標示；沒有快取就明示無資料，不假裝已收集。PWA 已快取的 App 可離線重新開啟，第一次使用仍需載入 App。
- 切換城市或離開頁面中止過期請求，快取按國家、城市中心座標、時區隔離。不把上一城市結果顯示在新城市下。
- 快取與設定使用獨立 `travel-info:v1:*` localStorage，與使用者 IndexedDB 行程／訂單分開；不是備份檔的一部分。快取損壞、儲存被拒或空間不足不讓 App 白畫面；無法保存時提供提示。

## 外部查詢與限制

- 自動查詢只用已知公開城市中心座標及時區；更換城市時另將使用者輸入的城市名稱送 Open-Meteo 地名服務。
- 不傳送旅程名稱原文、訂位代號、住宿地址、旅客、人數、筆記或附件。不使用帳號或 API 金鑰。公開資料查詢不會修改使用者的行程、排序、提醒或訂單。
- Open-Meteo geocoding／weather 與 Wikipedia 請求使用 HTTPS、不帶 cookies，關閉 referrer。外部服務仍會看到一般連線資訊。
- 請求有 15 秒逾時，遵守快取與退避；公開 API 可能有限流、覆蓋不足或格式變更。取不到資料就顯示狀態，不編造補值。
- Wikipedia 不同城市的中文條目覆蓋率不同，不是完整景點／車站目錄；跨境、離島或多城市旅行需自行選擇目前要看的城市。
- 初步試過 OpenStreetMap Overpass 主站 406 與另一實例逾時，改用已驗證可用的 Wikipedia；沒有繞過網路政策。

## 實作與驗證入口

- `src/lib/travelInfo.ts`：城市推定、公開 API、資料清理、時間／距離、分別更新與快取。
- `src/components/TravelInfo.tsx`：城市選擇、分頁、自動／手動更新、前景／連線事件、請求取消與 UI 狀態。
- `src/lib/travelInfo.test.ts`：天氣零值與未知值、日期、分類、惡意 URL、城市隔離、成功時間、部分失敗、取消及儲存錯誤。
