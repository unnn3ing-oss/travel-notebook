# AI 匯入「複製提示詞」架構

適用目前旅行手帳 JSON v2。App 行程頁 → AI 匯入 → 複製提示詞，會帶入目前旅程名稱、日期、時區、幣別與人數；這些是核對參考，不代替訂單事實。

可先看 [完整提示詞文字檔](handoff-assets/import-prompt-framework/prompt-example.txt)。檔案中的旅程是虛構示範，實際操作以 App 複製的當前旅程版本為準。

## 給使用者的操作方式

1. 複製提示詞到你要使用的 AI 對話，搭配已授權的 Gmail／Notion，或貼上信件、筆記、上傳訂單 PDF／圖片。
2. 如果 AI 讀不到信箱附件，依它列出的清單，把原始 PDF 上傳到同一個 AI 對話。PDF 沒有座位時，還需要選位確認或更新通知；不猜座位。
3. 核對 AI 回傳 JSON 的訂單、日期、幣別與短筆記，再貼回 App。檢查預覽、勾選後才加入。
4. 重複訂單預設忽略，可在預覽選「覆蓋」並確認後更新原卡；多候選時需選定目標。空值保留原資訊，新筆記有內容時取代原筆記，附件保留。詳細比對及復原規則見[說明](import-ignore-overwrite.md)。來源與核對事項在該 AI 對話的 review，不會匯入 App。

App 本身沒有讀取信箱、Notion 或解析 PDF 的功能。讀檔、OCR、連接器權限取決於使用的外部 AI；提示詞不能繞過權限，也不能保證 PDF 原本包含座位。

## 八段處理流程

| 段落 | 目的 |
| --- | --- |
| 1. 任務與本次旅程 | 動態帶入六個參考欄位；資料不是額外指令 |
| 2. 可用來源與查找範圍 | 已授權連接器、貼文、直接上傳；按旅行日期找，不限收件日期 |
| 3. 附件取得與 PDF 補件 | 實讀相關頁面，缺附件先補件，按旅客與航段核對 |
| 4. 訂單版本與匯入範圍 | 最新有效版本、付款更新、排除取消、規劃與訂單區別 |
| 5. 八種類型與欄位對應 | 航班、住宿、交通、門票、餐廳、景點、租車、其他 |
| 6. 格式、選項與未知值 | 日期、時區、幣別、列舉、未知 null 與匯入限制 |
| 7. 旅途筆記與核對紀錄 | 最多三個必要行動短項；來源與查核留 review |
| 8. 輸出前自檢與格式 | 單一 JSON v2、只列實際項目、上限 100 筆、不要複製骨架 |

## 必須維持的欄位邊界

- 航班每航段一筆，座位依航段／旅客核對，航廈數字加 T；住宿一筆自動生成入住／退房兩卡。
- 交通路線缺少分鐘／票價會被現有 importer 按 0 計算。因此範本要求先補齊數字；不能補齊時不輸出不完整路線，並在 review 說明。
- 票種單價與交通 fare 是旅程幣別數字，不擅自換匯；不同幣別原價保留通用 price，不能當相同幣別計算。
- 餐廳、景點、租車與其他使用共通欄位，沒有 restaurant／rental 專屬物件。跨日還車日期時間留必要短筆記。
- 提醒屬使用者偏好；沒有指示用 null，沿用 App 預設。未知座位、早餐、付款、費用不因 UI 預設而當成已知事實。
- review 不儲存、不在 App 顯示。要回查來源需保留外部 AI 對話；不把它整段塞進筆記。

完整可接收欄位見 [欄位參考](ai-import-field-reference.md)。不改 JSON parser、資料庫或舊卡片。

## 維護來源與驗證

提示詞與八類欄位骨架集中於 `src/lib/importPrompt.ts`；`src/lib/importer.ts` re-export `importPrompt`，既有複製按鈕沿用同一入口。文字檔及欄位參考的 JSON 區塊是從這份來源匯出，更新時一起同步；不要各維護一套獨立格式。

以 `npm test`、`npm run build` 驗證，並在瀏覽器實測複製、貼回 JSON、匯入預覽、儲存與重新載入。使用虛構資料；沒有外部 AI／真實信箱或 PDF 端到端測試，不能宣稱已實測附件權限或辨識率。
