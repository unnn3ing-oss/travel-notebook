# 旅行手帳

排行程、存備案，旅途中只看現在和下一站。資料只存在這支手機（IndexedDB），不需要帳號，也不需要網路。

## 給接手 AI

先讀 [AGENTS.md](AGENTS.md)、[專案交接](docs/ai-handoff.md) 與 [任務交接索引](docs/handoffs/README.md)。Claude 也可從 [CLAUDE.md](CLAUDE.md) 進入。收到需求並提出方向後，改程式前先保存 GitHub handoff checkpoint；完整命令與授權範圍見 AGENTS.md。

## 目前有的功能（v0.1）

- **總覽**：出發倒數、出發前準備的期限（例如「要在 11/08 前完成（還剩 3 天）」）、預訂狀態
- **今日**：現在、下一站、稍後；依目前時間提醒幾點要出發去搭車
- **行程**：依日期排卡片，可以新增、編輯、刪除；時間重疊時會提醒，並能把後面的行程一起延後
- **交通班次**：每條路線存班次，依目前時間判斷每一班還來不來得及
- **改用備案**：主方案不行時換成備案，可以復原
- **準備清單**：期限從出發日往前算，改出發日會自動更新

預訂狀態只有三種：**還沒訂**、**已訂購**（付款了，還沒收到確認信）、**訂單確認**（收到確認信了）。

起始頁提供「開始新旅程」與「回顧過去旅行」。若有進行中或即將出發的旅程，會依出發日期排序，以黃色入口顯示在最上方。首次使用不會自動加入範例資料；既有旅程資料會保留。

介面以提供的「旅行手帳 App 介面」設計為準，包含手機版四項導覽（總覽／今日、行程、預訂、必備）、清單／時間軸，以及桌機多日規劃欄。證件、花費與旅程資料儲存在本機 IndexedDB，可在「必備 → 設定與備份」匯出 JSON 備份。

## 新增行程

在行程頁點右下角 ＋，依類型填寫交通、航班、住宿或門票。取消表單不會留下空卡片；儲存時會依開始時間插入當天，保留其他卡片的相對順序。

- 交通可編排步行與多段轉乘、加入備用路線，並指定主要路線；總時間與費用由路段加總。
- 住宿一次產生入住、退房兩張關聯卡片，修改日期不會重複新增，刪除時會一併處理。
- 航班依兩地時區計算飛行時間，可設定起飛前 3 小時的機場提醒；門票保存票種、張數與取票方式。
- 取消期限提醒可關閉。提醒中心沿用目前版本的通知能力：App 開啟時檢查，仍受安靜時段與通知權限限制。

## 匯入與查看行程

AI 匯入提示詞使用 version 2，依現有航班、住宿、門票、交通表單提供完整欄位；仍可讀取舊版 JSON。航班號碼與訂位代號分開保存，住房地址、房型、費用、筆記與交通路段會一併保留。未知內容在匯入預覽和詳細頁標示為未提供，不會補成訂單事實；舊版已丟失的欄位需要重新匯入原始訂單。

點清單或時間軸卡片會先查看完整資訊與筆記，頁尾提供左右並排的「編輯／刪除」。編輯時沿用原本資訊卡片，文字切換為輸入欄位，底部為「取消／儲存」，可更改日期；長按重排保留。紅色刪除按鈕會要求再次確認，住宿的入住、退房卡及附件會一併刪除。

行程清單的航班卡以飛機與雲的機票造型呈現，其他類型使用小插圖點綴，入住／退房各有對應圖示。行程頁首依時間最早的航班目的地顯示日本、韓國、台灣、新加坡、香港或馬來西亞地標；沒有明確對應時使用中性旅途插圖。主題不會因回程或長按重排而跳動，原有資料保持不變。

## 模擬旅途中的時間

網址加上 `?now=`，就能看到某個時間點的畫面，例如：

```
/?now=2026-11-21T13:44
```

## 開發

```bash
npm install
npm run dev     # 本機開發
npm test        # 單元測試
npm run build   # 型別檢查＋建置到 dist/
```

技術：React 19、Vite 8、TypeScript、Dexie（IndexedDB）、vite-plugin-pwa。部署在 Vercel，push 到 `main` 會自動更新。
